# CPU generation admission

Generation configuration can opt into a shared FIFO budget. Missing, zero and `auto` limits resolve conservatively to one; GPU slots cannot exceed total slots. When the shared CPU budget is disabled, ordinary CPU generation and pHash retain legacy scheduling, threading and batching, even when an Intel backend is selected. Intel probes and execution still have mandatory admission using the same configured limits. Enabling the shared CPU budget makes all covered work use one scheduler. An explicit budget applies to individual subprocess and composition stages rather than whole scene tasks, avoiding nested admission deadlocks.

Metadata probes, frame counting, FFmpeg generation, canonical CPU pHash and sprite publishing use cancellable admission. Probe execution deadlines start after admission. Cancellation and failed encoding release permits and preserve existing sprite output. Canonical pHash retains its existing seek, scale and hash algorithm; under the shared budget its frame decoder concurrency is one. Stored hashes are not migrated.

Sprite frame extraction runs independent canonical seeks concurrently when a budget is active. GPU sheets compose scaled hardware surfaces in a resident FFmpeg operation under the shared GPU/total process limits; software tile extraction uses the total-process limit, bounded by tile count. Every subprocess still acquires the same shared scheduler across scenes. Results retain their requested indices, and a failed attempt cancels and drains all its workers. GPU selection fails explicitly instead of retrying with CPU rendering. With shared CPU admission disabled, unrelated ordinary CPU sprites retain serial extraction. The existing process and thread settings control throughput; there is no separate fixed sprite-worker cap.

The Windows native pipeline uses separate pools, so it is bypassed when an Intel backend or a shared generation budget is selected. Decoder, filter and encoder thread controls limit their respective FFmpeg stages; a configured thread count is not an operating-system CPU quota. Images and unrelated scanning or plugins are not covered by every media-generation limit.

Animated WebP requires explicit software selection and uses the corrected lossless/compression-6 settings. A GPU request fails explicitly because no supported lossless animated GPU encoder exists. Lossless output costs more CPU than the historical preset-overridden lossy output; that historical output must not serve as its performance baseline. Resident Intel MP4 and JPEG generation use these same admission limits, including capability probes, VR/HDR processing and cancellation cleanup.
